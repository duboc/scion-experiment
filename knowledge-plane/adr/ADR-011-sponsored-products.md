# ADR-011: Sponsored Products / Retail Media (Native Ads with Real-Time Budget)

- **Status:** Accepted (Issue #35; reviewed APPROVED 2026-10-14)
- **Covered Issue:** GitHub **Issue #35** — "Sponsored Products / Retail Media (Injeção de anúncios nativos com controle de budget real-time)"
- **Migrations:** `src/iac/migrations/023_ad_campaigns.sql`, seed `023b_seed_ad_campaigns.dml.sql`

## Context
psearch returns organic results only. Retail Media requires mixing paid (sponsored) products into the same response, at fixed native slots, only when they are relevant to the query, and charging advertisers in real time **without ever overspending** a campaign budget. The issue asks for an `AdCampaigns` table in Spanner (ACID budget burn) and a third CTE `SponsoredMatches` in the hybrid query that injects up to K sponsored items above a relevance threshold at fixed positions (e.g. 1, 4, 8).

Constraint discovered in the current pipeline: after `HybridSearchDetailed`, `handlers.go` re-orders results with Stage-2 LTR (`services.Rerank`, ADR-006) and session personalization (ADR-007). Slot positions decided inside SQL would be scrambled. Therefore **selection** happens in SQL, **placement** happens in Go as the very last step.

## Decision
1. **Schema (`023_ad_campaigns.sql`, online DDL):**
   - `ad_campaigns` — `campaign_id STRING(64) NOT NULL` (PK), `tenant_id STRING(64) NOT NULL`, `advertiser STRING(128)`, `product_id STRING(64) NOT NULL`, `cpc_micros INT64 NOT NULL` (bid per click), `budget_micros INT64 NOT NULL`, `spent_micros INT64 NOT NULL DEFAULT (0)`, `status STRING(16) NOT NULL` (`active` | `paused` | `exhausted`), `start_at TIMESTAMP`, `end_at TIMESTAMP`, `updated_at TIMESTAMP OPTIONS (allow_commit_timestamp=true)`. Secondary index `ad_campaigns_by_tenant_product (tenant_id, product_id) STORING (cpc_micros, budget_micros, spent_micros, status, start_at, end_at)`.
   - `ad_clicks` — `campaign_id STRING(64) NOT NULL`, `click_id STRING(64) NOT NULL`, `product_id`, `cost_micros INT64`, `clicked_at TIMESTAMP OPTIONS (allow_commit_timestamp=true)`; PK `(campaign_id, click_id)`, `INTERLEAVE IN PARENT ad_campaigns ON DELETE CASCADE`.
   - Money is integer **micros** (no float rounding in budget math).
2. **Selection — 3rd CTE `sponsored_matches` in the hybrid SQL** (`buildHybridSQLMode`): selects from `ad_campaigns` JOIN `products` where campaign is `active`, `CURRENT_TIMESTAMP()` within `[start_at, end_at]` (NULL = open), `spent_micros + cpc_micros <= budget_micros`, `tenant_id = @tenant_id`, the product passes the **same `catalogFilterSQL`** (visibility, channel, locale, price, color/size, B2B assortment) and is **in stock**, and is **relevant**: text match `SEARCH(title/description tokens, @query_text)` OR (vector leg present) `1 - COSINE_DISTANCE(<column>, @query_embedding) >= @ad_min_similarity`. Ranked by `cpc_micros * relevance` (ties by `campaign_id`), `LIMIT @ad_k`. Its rows are emitted in the same statement with `is_sponsored = TRUE` (+ `campaign_id`, `cpc_micros`), organic rows `is_sponsored = FALSE`. Lexical-only mode uses the text condition only; vector-only (image) mode uses the vector condition only. Bound `@params` only.
3. **Placement — Go, last step in `Controller.Search`** (after LTR, session re-rank, pagination): `services.InjectSponsored(organic, sponsored, slots)`. Default slots `[1,4,8]` (1-based, env `AD_SLOTS`), `K = len(slots)` (env `AD_MAX`, default 3), `AD_MIN_SIMILARITY` default `0.55`. If a sponsored product also appears organically **the organic copy is removed** (no duplicates). If fewer organic results than a slot index, ads are appended in order, never exceeding K; zero organic results ⇒ zero ads (ads never rescue a zero-result page). Ads only on page 1 / non-browse queries with a text or image query; `ads=false` request param disables injection.
4. **Real-time budget burn — `POST /api/ads/click`** `{campaign_id, click_id}` runs a single Spanner `ReadWriteTransaction`: read campaign; reject if not `active` or `spent_micros + cpc_micros > budget_micros`; `INSERT ad_clicks` (duplicate `click_id` ⇒ `AlreadyExists` ⇒ idempotent no-charge, return `charged=false`); `UPDATE spent_micros = spent_micros + cpc_micros`, and set `status='exhausted'` when the next click would overspend. Serializable transactions + the read-then-write within one txn guarantee **no overspend under concurrency**. `click_id` is an opaque random token returned per sponsored item in the search response (`ad_click_id`). Charging is CPC only; impressions are not written on the hot search path.
5. **Campaign admin — `/api/ads/campaigns`**: `GET` (list, tenant-scoped), `POST`/`PUT /:id`/`DELETE /:id` — all writes call `c.authorizeAdmin(ctx)`; validate `cpc_micros > 0`, `budget_micros >= cpc_micros`, known `product_id`.
6. **API:** `SearchResult` gains `sponsored bool`, `ad_campaign_id`, `ad_click_id` (omitempty). `SearchResponse` gains `sponsored_count`. Sponsored items are **excluded from facets, `total`, LTR features and session centroid**. OpenAPI contract updated.
7. **Parity (Invariant 1):** in-memory `MemoryAdStore` mirrors campaigns, selection rules (text match / threshold, catalog filters, budget check) and atomic click charging (mutex), seeded with the same demo campaigns as `023b`, so `go test -race ./...` covers injection, dedupe, budget exhaustion and concurrent-click no-overspend offline.
8. **`cmd/sqlcheck`:** add checks for the hybrid SQL with the sponsored CTE and for the campaign list query.

## Consequences
- Ads are bounded (K slots, relevance threshold, catalog filters) so they cannot degrade organic relevance beyond the fixed slots.
- Budget correctness relies on Spanner serializable read-write txns; click spam is bounded by idempotent `click_id` but not fraud-filtered (out of scope).
- Placement after re-ranking keeps slot positions stable and deterministic.
